# yadisk_client

Python-библиотека и CLI **`yd` / `yadisk`**, версия **0.3.1**. Авторизация, файлы и папки, параллельная передача, прогресс, метаданные, корзина и публичные ссылки. Python 3.10+. Пакет для локальной установки, в PyPI не опубликован.

## Автоматическая резервная копия и приложение Mac — 0.3.0

Приложение **«Яндекс Бэкап»** показывает состояние копирования в строке меню. Доступны ручной запуск, пауза/возобновление, открытие Диска, журнала и настройки исходной папки и интервала. В строке меню постоянно видны «Проверка», «Сохранение», «Готово», «Пауза» или ошибка. Меню отличает первую копию от следующих запусков, показывает время успешного завершения и следующей проверки. При проверке показываются найденные файлы и текущая папка: общий процент на этом этапе ещё неизвестен. Общий процент и оставшееся время не показываются: объём изменений определяется по мере обхода папок. Показываются завершённые файлы, переданные байты и скорость; дождитесь «Копирование завершено ✓». «Открыть Яндекс.Диск» запускает установленное приложение macOS. Закрытие значка не останавливает службу; для остановки копирования нажми «Пауза».

По умолчанию: рабочий стол текущего пользователя, интервал 15 минут, 4 потока, назначение `/Backups/<имя-компьютера>/Desktop`. Запуск при входе пользователя в macOS. Во время сна копирование не выполняется, после пробуждения работа продолжается. Сетевые ошибки вызывают повторную попытку через минуту. Пауза прекращает планирование новых файлов; текущие передачи сначала завершаются.

- `current/` — актуальные копии файлов. Локальное удаление не удаляет их из облака.
- `history/<дата-и-id-запуска>/` — предыдущие версии изменённых файлов. Автоматического удаления истории нет.
- `.staging/` — временная область. Текущая копия заменяется только после проверки новых байтов и сохранения старой версии. Успешно завершённая временная папка очищается; при неизвестном результате операции может остаться для восстановления.

Каждый запуск сравнивает содержимое по MD5: изменения прежнего размера также обнаруживаются. Файлы каждой папки передаются сразу после её проверки, без предварительного обхода всего облачного дерева и создания всех папок. Чтение метаданных, создание папок и загрузка в собственную временную область при сетевой ошибке повторяются до пяти раз с паузой 10 секунд; пауза пользователя прерывает ожидание. При исчерпании попыток служба повторяет проход через минуту и пропускает сохранённые файлы по контрольным суммам. Неопределённый результат перемещения сверяется с облаком; при невозможности подтвердить результат проход останавливается безопасно. Полное первое копирование большого дерева может занять много времени; следующие запуски передают только отличающиеся файлы. Хеширование всё равно читает локальные файлы. Одновременные запуски службы блокируются файловой блокировкой. Используй отдельное назначение, не изменяй `current` параллельно другим приложением.

Стандартные исключения: зависимости и кэши (`node_modules`, `.venv*` (включая `.venv1`), `venv`, `site-packages`, `__pycache__`, `.cache`, `dist`, `build` и т. п.), `.env`/`.env.*`, `.ssh`, `.aws`, `*.pem`, `*.key`, файлы OAuth-токенов. Символические ссылки пропускаются. Скрытые файлы, не попавшие под исключения, включаются; `.git` сохраняется. Это копия содержимого файлов, а не образ Mac; согласованные снимки работающих баз данных не создаются.

Настройки и локальный статус находятся в `~/Library/Application Support/YandexBackup/`: `config.json`, `status.json`, `last_result.json`, `backup.log`. Реальный OAuth-токен остаётся в исходном `.env`, его содержимое не копируется в настройки. Изменения настроек применяются со следующего запуска. Журнал вращается автоматически.

Из Python:

```python
with YandexDisk.from_env(".env") as disk:
    result = disk.backup_tree("./project", "/Backups/project", exclude=[".env", "node_modules"])
    print(result.uploaded, result.updated, result.unchanged, result.failed)
    assert result.ok
```

Из CLI:

```sh
yd backup ./project disk:/Backups/project --exclude .env --exclude node_modules --workers 4
# Управление установленной службой:
"$HOME/Library/Application Support/YandexBackup/venv/bin/yadisk-backup" --status
"$HOME/Library/Application Support/YandexBackup/venv/bin/yadisk-backup" --pause
"$HOME/Library/Application Support/YandexBackup/venv/bin/yadisk-backup" --resume
```

`BackupResult.ok` истинен только при завершённой копии без ошибок и паузы. `BackupProgress.done` обозначает завершение вызова, включая неудачное; успешность проверяй по результату. Список `pending` содержит незавершённые файлы, `staging_leftovers` — временные объекты с неизвестным результатом.

Для повторной установки на Mac: собрать `.app` командой `macos/build_menu_app.sh`, затем выполнить `macos/install.py --wheel /path/to/package.whl --app-bundle /path/to/app.app --env-file /path/to/.env`. Установщик создаёт отдельное Python-окружение, приложение в `~/Applications` и два LaunchAgent в `~/Library/LaunchAgents`. Существующие настройки сохраняются. macOS может потребовать разрешение доступа к Desktop.

Отключение автозапуска без удаления облачных данных:

```sh
launchctl bootout "gui/$(id -u)/local.egor.yandexbackup.worker"
launchctl bootout "gui/$(id -u)/local.egor.yandexbackup.menu"
```

Для постоянного отключения также убери два соответствующих `.plist` из `~/Library/LaunchAgents`. Пауза через меню сохраняется между перезапусками и обычно удобнее полного отключения.

## CLI: как hdfs / aws s3

После установки доступны команды `yd` и `yadisk`. Также можно выполнить `python -m yadisk_client`. В распакованной папке есть исполняемый файл `./yd`: он запускает исходники без установки пакета, если зависимости уже доступны в Python.

Один раз укажи расположение своего `.env` в текущем терминале:

```sh
export YADISK_ENV_FILE="$HOME/.config/yandex-backup/.env"
yd auth check
yd df
yd ls disk:/
```

Вместо переменной можно передавать `--env-file /path/to/.env` в каждой команде, до или после имени операции. `.env` по умолчанию ищется в текущей папке.

```sh
# Папки и просмотр
yd mkdir -p disk:/Backup/Work
yd ls disk:/Backup -r
yd stat disk:/Backup/Work/report.zip
yd du disk:/Backup

# Одиночные файлы
yd put ./report.zip disk:/Backup/Work/report.zip
yd get disk:/Backup/Work/report.zip ./report-copy.zip

# Содержимое папки, фильтры и четыре рабочих потока
yd put -r ./project disk:/Backup/project \
  --exclude node_modules --exclude .venv --exclude '*.tmp' --exclude .env \
  --workers 4
yd get -r disk:/Backup/project ./restored-project --workers 4

# Несколько локальных файлов в существующую папку
yd put ./a.zip ./b.zip ./c.zip disk:/Backup/Work/ --workers 3

# cp определяет направление по префиксу disk:
yd cp ./report.zip disk:/Backup/report.zip
yd cp disk:/Backup/report.zip ./report-copy.zip
yd cp disk:/Backup/report.zip disk:/Backup/report-v2.zip

# Операции внутри облака
yd mv disk:/Backup/report-v2.zip disk:/Backup/renamed.zip
yd rename disk:/Backup/renamed.zip final.zip
yd share disk:/Backup/final.zip
yd unshare disk:/Backup/final.zip

# Корзина
yd rm disk:/Backup/final.zip
yd trash ls --json
# Взять точное значение path из списка корзины:
yd trash restore 'trash:/opaque-path-from-list'
# Безвозвратно удалить один конкретный элемент корзины:
yd trash rm 'trash:/opaque-path-from-list'
```

### Семантика путей и перезаписи

- `put`: источники локальные, назначение на Диске. `get`: источник на Диске, назначение локальное. В этих командах удалённый префикс `disk:` необязателен.
- `cp`: нужен `disk:/...` хотя бы с одной стороны. Два удалённых пути — серверная копия; данные через Mac не скачиваются. Копирование только между локальными путями не поддерживается.
- **Рекурсивный `put/get` копирует содержимое исходной папки точно в указанную папку назначения.** Например, `put -r ./project disk:/Backup/project` создаёт `/Backup/project/file`, а не `/Backup/project/project/file`. Пустые папки сохраняются.
- При передаче одного файла существующая папка назначения означает «положить файл внутрь с исходным именем». У удалённого назначения можно также указать завершающий `/`. Родительская папка одиночного файла должна существовать; создать её можно `mkdir -p`.
- Для серверных `cp` и `mv` назначение всегда **точный новый путь**, без автоматического добавления имени внутрь существующей папки. Для серверной копии папки нужен `-r`; `--exclude` здесь не применяется — сервер копирует весь объект.
- Перезапись включается только через `--overwrite`. Повторный запуск без этого флага обнаружит существующие файлы и вернёт ошибки, а не пропустит их молча. Синхронизация и автоматический пропуск неизменившихся файлов не реализованы.
- `rm` отправляет объект в корзину. Для папки требуется `-r`. `rm --permanent` удаляет выбранный объект безвозвратно. `trash rm` также необратим. Удаление корня Диска и неявная очистка всей корзины запрещены.
- Переносы и удаления при потере ответа не повторяются автоматически: результат может быть неизвестен, поэтому сначала проверь состояние через `ls/stat`.

### Вывод и коды завершения

В интерактивном терминале передача показывает процент, среднюю скорость, примерное оставшееся время и число завершённых файлов. Прогресс идёт в stderr; `--no-progress` его отключает. В режиме `--json` stdout содержит один JSON-результат, прогресс отключён. Для `ls` размер указан в байтах; размер папок рассчитывает `du`. `df` возвращает `total_space`, `used_space`, `free_space`, `trash_size` и лимит файла в байтах.

Коды: `0` — успех; `1` — ошибка, включая частично неудачную очередь; `2` — неправильные аргументы; `130` — прерывание. Для очереди JSON содержит `completed`, `failed` и `skipped`. Ошибка одного файла не отменяет остальные; уже завершённые передачи не откатываются.

Команды: `auth check/login/refresh`, `put`, `get`, `cp`, `ls`, `stat`, `du`, `df`, `mkdir`, `mv`, `rename`, `rm`, `trash ls/restore/rm`, `share`, `unshare`. У каждой есть `--help`.

### OAuth из CLI

```sh
# Нужны client_id, client_secret и redirect_uri в .env
yd auth login --browser --token-file ./disk-token.json
# Вставить полный callback URL после согласия в браузере.
yd --token-file ./disk-token.json auth check
yd --token-file ./disk-token.json ls disk:/
yd auth refresh --token-file ./disk-token.json
```

`login` по умолчанию создаёт `.yadisk-token.json`; чтобы заменить существующий файл, нужен `--overwrite`. Файл имеет права `0600` на macOS/Linux. Команда `refresh` обновляет выбранный файл атомарно. Для использования сохранённого JSON указывай `--token-file`; он имеет приоритет над access-токеном из `.env`. Токены не печатаются в stdout. Исходный `.env` не изменяется.

## Python API: новые возможности

```python
from pathlib import Path
from yadisk_client import YandexDisk, Progress


def show_progress(event: Progress):
    print(event.percent, event.bytes_per_second, event.eta_seconds)


with YandexDisk.from_env(".env") as disk:
    print(disk.info())
    print(disk.listdir("/"))
    print(disk.stat("/report.zip"))
    print(disk.size("/Backup"))
    print(disk.exists("/Backup"))

    disk.mkdir("/Backup/projects", parents=True, exist_ok=True)
    result = disk.upload_tree(
        "./project", "/Backup/projects/project",
        exclude=["node_modules", ".venv", ".env", "*.tmp"],
        workers=4, progress=show_progress,
    )
    if not result.ok:
        print(result.failed)

    result = disk.download_tree(
        "/Backup/projects/project", "./restored-project",
        workers=4, progress=show_progress,
    )

    result = disk.upload_many(
        [("./a.zip", "/Backup/a.zip"), ("./b.zip", "/Backup/b.zip")],
        workers=2, progress=show_progress,
    )

    disk.copy("/Backup/a.zip", "/Backup/a-copy.zip")
    disk.move("/Backup/a-copy.zip", "/Backup/moved.zip")
    disk.rename("/Backup/moved.zip", "renamed.zip")
    public_url = disk.publish("/Backup/renamed.zip")
    disk.unpublish("/Backup/renamed.zip")
    disk.remove("/Backup/renamed.zip")  # в корзину
    trash = disk.trash_list()
    # Восстанавливай только выбранный объект по его точному trash path:
    # disk.restore(trash_path, name="restored.zip", overwrite=False)
    # disk.trash_delete(trash_path)  # безвозвратно
```

`listdir()` возвращает непосредственные элементы, `walk()` — итератор всех потомков. Пагинация API обрабатывается автоматически. `size()` рекурсивно считает `bytes`, `files`, `directories`; сами метаданные папки могут не содержать общий размер. `copy`, `move`, `remove`, `restore` и операции корзины дожидаются завершения асинхронного ответа сервера (до 300 секунд общего ожидания, плюс время сетевых запросов).

`upload_tree` и `download_tree` возвращают `BatchResult`: список удачных передач, ошибки по отдельным файлам и пропущенные пути. `workers` — от 1 до 32, по умолчанию 4. Очередь ограничена числом рабочих потоков, HTTP-соединения переиспользуются внутри каждого потока. План файлов и результаты хранятся в памяти.

### Исключения и особенности рекурсивной передачи

Шаблоны передаются списком (`exclude=[...]`), в CLI флаг можно повторять. Шаблон без `/` проверяется по каждому компоненту имени: `node_modules` исключит такие папки на любой глубине, `*.tmp` — соответствующие файлы. Шаблон с `/` проверяется по относительному POSIX-пути: `build/**` исключает каталог `build` и содержимое. Это glob-сопоставление, не полная семантика `.gitignore`: отрицательные правила и отдельное управление `**` не реализованы. Символ `*` в шаблоне полного пути может сопоставлять `/`. Исключённые папки не обходятся; скрытые файлы включаются, если их явно не исключить.

Локальные символические ссылки при рекурсивной загрузке пропускаются. Права доступа, владельцы, extended attributes и времена изменения не сохраняются: передаётся содержимое файлов и структура папок. При скачивании отклоняются опасные пути, ссылки внутри назначения и имена, совпадающие без учёта регистра/Unicode-нормализации. Это предотвращает потерю файлов на типичной файловой системе Mac. Для папок с именами, различающимися только регистром, сначала потребуется переименование.

Прогресс одиночного файла доступен через `upload(..., progress=callback)` и `download(...)`. `Progress` содержит путь, направление, байты, общий объём, время, номер попытки, признак `done` и счётчик файлов. В очереди callback получает суммарный прогресс; вызовы сериализованы, но могут происходить из рабочих потоков. Callback должен быть коротким и не менять данные очереди. При повторе передачи счётчик байтов может уменьшиться. `done=True` приходит после проверки; 100% переданных байтов ещё может означать ожидание проверки. Скорость и ETA приблизительные.

## Быстрый старт с существующим .env

```python
from pathlib import Path
from yadisk_client import YandexDisk

with YandexDisk.from_env(
    Path.home() / ".config/yandex-backup/.env"
) as disk:
    disk.check_auth()

    uploaded = disk.upload("report.zip", "/report.zip")
    print(f"Загружено {uploaded.size} байт")

    downloaded = disk.download("/report.zip", "report-copy.zip")
    print(f"Скачано {downloaded.size} байт")
```

Локальные пути в примере относятся к текущему каталогу вызывающей программы. В `upload()` указываются существующий локальный файл и полный путь файла на Диске. Родительская папка на Диске должна существовать. В `download()` указывается полный путь локального файла; его родительская папка также должна существовать.

Поддерживаются новые имена переменных и имена из имеющегося `.env`:

| Новое имя | Совместимое старое имя |
|---|---|
| `YANDEX_ACCESS_TOKEN` | `yandex_access_token` |
| `YANDEX_CLIENT_ID` | `yandex_ClientID` |
| `YANDEX_CLIENT_SECRET` | `yandex_Client_secret` |
| `YANDEX_REDIRECT_URI` | `yandex_Redirect_URI` |

Переменные окружения имеют приоритет над `.env`. Внутри одного источника новое имя имеет приоритет. `from_env()` без аргументов читает `.env` из текущей рабочей папки. Реальный `.env` не входит в библиотеку; есть только пустой `.env.example`. Для готового токена нужны только права чтения/записи Диска и сам токен — `client_id` и `client_secret` не требуются.

Можно передать токен непосредственно из своего хранилища секретов:

```python
with YandexDisk(token=access_token) as disk:
    disk.check_auth()
```

`check_auth()` возвращает `True` при успешном запросе API; при недействительном токене выбрасывает `AuthenticationError`. Успешная проверка доступа сама по себе не подтверждает наличие права записи — это выясняется при загрузке.

## Получение нового токена

В приложении Яндекс OAuth должны быть настроены права `cloud_api:disk.read`, `cloud_api:disk.write` и Redirect URI. Используется Authorization Code с PKCE и проверкой `state`. Библиотека не запускает сервер перенаправления и не открывает браузер автоматически.

```python
from yadisk_client import OAuth

with OAuth.from_env(".env") as oauth:
    request = oauth.authorization_url()
    print("Открой в браузере:", request.url)

    # После согласия Яндекс перенаправит на Redirect URI.
    # Вставь полный URL из адресной строки с code и state.
    callback_url = input("URL после авторизации: ").strip()
    tokens = oauth.exchange_callback(callback_url, request)

    # Сохрани tokens.access_token и tokens.refresh_token
    # в своём хранилище секретов. Не выводи их в журнал.
```

Redirect URI должен совпадать с настройками OAuth-приложения. Вместо ручного ввода веб-приложение может передать библиотеке URL, полученный собственным обработчиком callback. При локальном Redirect URI браузер может показать ошибку подключения к отсутствующему серверу; адрес с параметрами можно скопировать из адресной строки.

Обновление выполняется явно, с refresh-токеном, выданным при авторизации:

```python
with OAuth.from_env(".env") as oauth:
    new_tokens = oauth.refresh(saved_refresh_token)
# Сохрани актуальные токены и создай YandexDisk(new_tokens.access_token).
```

Готовый access-токен из старого `.env` может не сопровождаться refresh-токеном. Получить refresh-токен из одного access-токена нельзя: нужно заново пройти авторизацию. Библиотека не редактирует `.env` и не обновляет токены в фоне. `expires_in` возвращается в секундах; сохранение срока действия остаётся за вызывающей программой.

## Передача файлов

По умолчанию существующие файлы **не перезаписываются**. Перезапись включается явно:

```python
disk.upload("report.zip", "/archive/report.zip", overwrite=True)
disk.download("/archive/report.zip", "report-copy.zip", overwrite=True)
```

Пути Диска принимаются в форме `/folder/file.bin` или `disk:/folder/file.bin`. Unicode, пробелы, `#` и `?` передаются как параметры API. Путь обязан включать имя файла, без завершающего `/`.

Что входит в базовую реализацию:

- Потоковая передача блоками по 1 МиБ, без чтения большого файла целиком в память.
- Повторное использование соединений, ограниченные повторы при сетевых сбоях и временных HTTP-ошибках, включая 429; учёт `Retry-After`.
- Повторная передача начинается с начала файла; докачка с позиции обрыва не реализована.
- Проверка размера и MD5: загрузка подтверждается метаданными Диска, скачивание — сравнением с метаданными перед загрузкой. MD5 здесь используется для обнаружения ошибок передачи, а не для криптографической аутентификации.
- Скачивание во временный файл рядом с назначением. Итоговый файл появляется после проверки; при ошибке временный удаляется. Существующий файл сохраняется до успешной замены.
- Защита от случайной перезаписи при появлении локального файла во время скачивания.
- OAuth-заголовок отправляется только в API. Подписанные ссылки на передачу используются отдельным HTTP-клиентом; перенаправления скачивания проверяются.
- Ошибки библиотеки не содержат токенов, подписанных URL или тел ответов. Если вызывающий код включает подробные сетевые журналы httpx/httpcore, он должен сам защищать их содержимое.

Во время загрузки исходный файл должен быть стабильным. Изменение обнаруживается проверкой отправленного содержимого, но если сервер уже принял изменённые байты, библиотека не откатывает удалённый файл. При потере ответа загрузки библиотека сначала проверяет, не завершилась ли она успешно. Не подтверждённую загрузку она не выдаёт за успешную.

Объект результата `TransferResult` содержит `local_path`, `remote_path`, `size`, `seconds`, `md5` и `megabytes_per_second`. Время включает чтение/проверку файла и обращения к API, поэтому оно отличается от чистой сетевой скорости.

## Найденное ускорение

По умолчанию `fast_upload=True`: в запросе ссылки и передаче файла используется User-Agent, совместимый с режимом `spoof_ua` backend Яндекс.Диска в rclone. На предварительных измерениях на этом Mac этот способ резко ускорял передачу. Это настройка совместимости, а не гарантированная скорость сервиса. Её можно отключить:

```python
disk = YandexDisk(access_token, fast_upload=False, max_attempts=4, timeout=600)
```

`timeout` — тайм-аут сетевой операции/ожидания активности, а не общий предел длительности всей загрузки. Для очень больших файлов Яндекс может долго готовить ответ; при необходимости увеличивай значение. Прямые вызовы одного клиента используй последовательно. `upload_many`, `upload_tree` и `download_tree` сами создают отдельные клиенты для рабочих потоков и закрывают их после завершения очереди.

## Ошибки

```python
from yadisk_client import AuthenticationError, APIError, IntegrityError, NetworkError

try:
    disk.upload("report.zip", "/report.zip")
except AuthenticationError:
    print("Нужно проверить или обновить токен")
except APIError as error:
    print("Ошибка API:", error.status_code)  # 403: права; 404: путь; 409: конфликт
except IntegrityError:
    print("Не удалось подтвердить содержимое файла")
except NetworkError:
    print("Сетевая операция не завершилась")
```

Ошибки локальных файлов (`FileNotFoundError`, `FileExistsError`, `PermissionError`) остаются стандартными исключениями Python. Неожиданный ответ API — `ProtocolError`. Все собственные ошибки наследуются от `YandexDiskError`.

Автотесты не используют сеть или реальные токены. Проверяются OAuth/PKCE, refresh, передача, Unicode, пустые файлы, повторы, потеря ответа, контрольные суммы, перенаправления и сохранность существующего файла при сбоях. Результат отдельной живой проверки записан в `VALIDATION.md`.
